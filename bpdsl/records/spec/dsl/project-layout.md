## What this is

Directory structure for a brewprint project. Covers `yaml/` / `renders/` / `render_index.yaml` placement, the `render_index.yaml` schema, renders output structure, render output filenames, index generation, and collision handling.

> Source: V01-ADR-043, V01-ADR-045, V01-ADR-046, V01-ADR-053

## Project root structure

```
{project-root}/
  yaml/               ← brewprint YAML files (single source of truth)
  renders/            ← auto-generated output from Go renderer
  render_index.yaml   ← render output grouping config (human-authored, optional)
  README.md
```

- `yaml/` holds the YAML source files — the single source of truth.
- `renders/` contains output generated by `brewprint render`. Humans do not edit it directly (git-committing for golden test purposes is acceptable, but only the renderer may modify content).
- `render_index.yaml` is optional. When omitted, the default behavior is "1 module = 1 group."

A project-root manifest file like `master.yaml` does not exist. Module structure is derived from the directory hierarchy under `yaml/`.

> Source: V01-ADR-043. The absence of `master.yaml` reflects V01-ADR-043 superseding the original V01-ADR-002 decision.

## yaml/ structure

Directories under `yaml/` form the module hierarchy. See [`spec:bpdsl.dsl.naming`](naming.md) §Module and folder hierarchy.

The parent of `yaml/` is the project root. The loader looks for `render_index.yaml` in the project root when the directory specified by `--yaml-root` has `yaml` as its basename.

> Source: V01-ADR-002, V01-ADR-043

## renders/ output structure

```
renders/
  index.md                  ← master index (link table to all groups)
  {group-id}/
    index.md                ← group index (list table of all renders in the group)
    model-{model-id}.md
    dag-{task-id}.md
    state-{fsm-id}.md
    seq-{scenario-id}.md
    wireframe-{fsm-id}-{state-id}.html
  _cross/
    er.md
    api.md
  _preview/
    wireframe.html
```

### Group directory

Each group is placed in a `{group-id}/` directory. See §render_index.yaml schema for `group-id` naming rules.

Renders placed directly under a group directory (present ones only):

- `model-{model-id}.md` — model file render
- `dag-{task-id}.md` — task DAG render
- `state-{fsm-id}.md` — FSM state diagram render
- `seq-{scenario-id}.md` — sequence diagram scenario render
- `wireframe-{fsm-id}-{state-id}.html` — wireframe render

In v1, nested module paths are not included in output filenames. Render output filenames are determined from the local ID of the semantic object.

Examples:

```text
yaml/payment/webhooks/task/process_payment.yaml
→ renders/commerce/dag-process_payment.md

yaml/payment/model/payment_request.yaml
→ renders/commerce/model-payment_request.md
```

If multiple render outputs within the same group resolve to the same relative path, the renderer / placement validation stops with an error. Silent overwrite is prohibited.

> Source: V01-ADR-053

### `_cross/` — cross-module views

Views that span multiple modules (ER / API Table) are placed in `_cross/`. The underscore prefix is reserved to distinguish these from normal group IDs.

Future cross-cutting views (global event flow, etc.) will be added under this directory.

### `_preview/` — preview harness

The wireframe preview harness is placed at `_preview/wireframe.html`.

> Source: V01-ADR-043, V01-ADR-046

## render_index.yaml schema

### Top-level structure

```yaml
groups:
  - id: auth
    label: Authentication
    modules: [auth]
  - id: commerce
    label: Commerce
    modules: [cart, order, payment]
```

| field | type | required | description |
|---|---|---|---|
| `groups` | array | required | List of group definitions. Empty array is a validation error. |

### Group object

| field | type | required | description |
|---|---|---|---|
| `id` | string | required | Group identifier. Becomes the `renders/{id}/` directory name. |
| `label` | string | optional | Human-readable display name. Defaults to `id` when omitted. |
| `modules` | array[string] | required | List of module names belonging to this group. Empty array is a validation error. |

### Group id / module naming rules

- Allowed characters: `[a-z0-9_]` (lowercase alphanumerics and underscores)
- Underscore prefix (`_`) is a **validation error** — reserved to prevent collision with `_cross/` / `_preview/`
- Empty string is a validation error
- Module names follow the same rules (since the implicit group id is the module name itself)

```yaml
# OK
- id: commerce
- id: payment_webhook

# NG (validation error)
- id: _internal
- id: Commerce
- id: ""
```

### Module uniqueness

Each module may belong to at most one group. A module name appearing in multiple groups is a validation error.

### Uncovered module handling

If a module under `yaml/` does not belong to any group in `render_index.yaml`, it is treated as an implicit group whose id equals the module name.

Implicit groups are appended after explicit groups in alphabetical order. A warning is emitted; it is not an error.

### groups array ordering

The order of entries in the `groups` array determines the row order in `renders/index.md` and the display order in each group `index.md`.

Implicit groups are appended after explicit groups in alphabetical order.

### Nested module handling

Only the top-level module name is specified in the `modules` field. Slash-separated paths (`payment/webhooks`) are a validation error.

When a nested module (e.g., `payment/webhooks`) is included in a group via its parent module (`payment`), child modules are also included in the same group. A child module cannot be split into a different group.

## Master index.md format

```markdown
# {project-name} render index

| group | Model | DAG | State | Sequence | Wireframe | ER | API |
|---|---|---|---|---|---|---|---|
| [Authentication](auth/index.md) | 1 | 1 | 1 | - | 2 | - | - |
| [Commerce](commerce/index.md) | 2 | 3 | 1 | 2 | 2 | - | - |
| *(cross)* | - | - | - | - | - | [er](_cross/er.md) | [api](_cross/api.md) |
| *(preview)* | - | - | - | - | [wireframe preview](_preview/wireframe.html) | - | - |
```

`{project-name}` is derived from the project directory name using these rules:

1. Split the directory name by `-`
2. Remove leading segments consisting of digits only
3. Title-case each segment
4. Apply known abbreviation uppercasing: `api` → `API`, `ec` → `EC`, `er` → `ER`, `ui` → `UI`, `uc` → `UC`

Examples:

```text
001-ec-checkout-flow → EC Checkout Flow
sample-api           → Sample API
```

If the project name cannot be derived, fall back to `brewprint`.

Group column display rules:

- Explicit group: `label` (or `id` if label is omitted)
- Implicit group: `id` (= module name)
- Cross row: fixed `*(cross)*`
- Preview row: fixed `*(preview)*`

Regular group row Model / DAG / State / Sequence / Wireframe columns show the count of render files in that group. Show `-` for zero. ER / API columns are always `-` for regular group rows.

The master `index.md` links only to group index files. Direct links to individual renders are provided by the group `index.md`. `_cross/` and `_preview/` may be linked directly as `*(cross)*` / `*(preview)*` rows.

> Source: V01-ADR-043

## Group index.md format

```markdown
# {group-label} render index

| kind | title | path |
|---|---|---|
| Model | payment_request | [model-payment_request.md](model-payment_request.md) |
| DAG | process_order | [dag-process_order.md](dag-process_order.md) |
| State | order | [state-order.md](state-order.md) |
| Sequence | checkout_flow | [seq-checkout_flow.md](seq-checkout_flow.md) |
| Wireframe | order-cart | [wireframe-order-cart.html](wireframe-order-cart.html) |
```

`{group-label}` uses the `label` from `render_index.yaml`; if omitted, uses `id`.

Row order:

1. By kind: `Model` → `DAG` → `State` → `Sequence` → `Wireframe`
2. Within the same kind: ascending by render output path

Column meanings:

| column | description |
|---|---|
| `kind` | Render kind: `Model` / `DAG` / `State` / `Sequence` / `Wireframe` |
| `title` | Output filename with prefix and extension stripped |
| `path` | Relative link from the group index |

`title` is generated by stripping these prefixes and extensions:

```text
model-payment_request.md                → payment_request
dag-process_order.md                    → process_order
state-order.md                          → order
seq-checkout_flow.md                    → checkout_flow
wireframe-order-checkout_screen.html    → order-checkout_screen
```

> Source: V01-ADR-043

## Preview index / title

The wireframe preview harness is output to `_preview/wireframe.html`. HTML title and page heading:

```text
{project-name} Wireframe Preview
```

Example:

```text
001-ec-checkout-flow → EC Checkout Flow Wireframe Preview
```

If the project name cannot be derived, fall back to `Wireframe Preview`.

> Source: V01-ADR-046
